# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

An NVDA screen reader add-on (Python, runs inside NVDA's process) that provides an ElevenLabs text-to-speech synthesizer driver. Requires NVDA 2025.1+ because it relies on NVDA's bundled `synthDrivers._sonic` time stretcher. There is no test suite; the code imports NVDA modules (`config`, `nvwave`, `synthDriverHandler`, `addonHandler`, etc.) and can only be run inside NVDA.

## Building and releasing

- Built with NV Access's add-on template (scons). Add-on metadata lives in `buildVars.py` (`addon_info`); `addon/manifest.ini`, the per-locale `addon/locale/<lang>/manifest.ini`, every `nvda.mo`, and `addon/doc/` (from the root `readme.md` + `style.css`) are generated by `scons` and git-ignored, so never edit or commit them. Don't change `sconstruct` or `site_scons/` (template files); customize through `buildVars.py`.
- The user builds locally with the venv at `..\env64`; its `Scripts\*.exe` launchers are broken (the venv was moved), so run `..\env64\Scripts\python.exe -m SCons` (output: `ElevenLabsTTS-<version>.nvda-addon`). `scons pot` makes a `.pot`. Needs GNU gettext (`msgfmt`/`xgettext`) on PATH. Leave building to the user unless asked.
- Releases are automatic (`.github/workflows/release.yml`): pushing to `main` with a change to `buildVars.py` builds with scons and creates GitHub release `v<version>` if that tag doesn't exist. Release notes are extracted from the matching `V<version>` entry in `changelog.md`. (The template's own tag-driven `build_addon.yml` was deliberately not adopted.)
- So a release = bump `addon_version` and replace `addon_changelog` in `buildVars.py` (then translate the new changelog in every `.po`) + add a `V<version> (MM/DD/YYYY):` entry at the top of `changelog.md`.
- `pyproject.toml` / `.pre-commit-config.yaml` carry the template's ruff and pyright settings; the existing code hasn't been reformatted to them.

## Layout

- `addon/synthDrivers/elevenlabs.py`: the whole synth driver (~2900 lines).
- `addon/synthDrivers/_elevenlabsSettings.py`: the add-on's own settings file and the DPAPI-encrypted API key (see below). The leading underscore keeps NVDA from listing it as a synthesizer.
- `addon/synthDrivers/_elevenlabsNavigation.py`: `NavigationSynth`, the second synthesizer that speaks outside say all (see "Navigation synthesizer" below).
- `addon/globalPlugins/elevenlabs_usage.py`: the "ElevenLabs TTS" category in NVDA's settings (`ElevenLabsSettingsPanel`, registered in `NVDASettingsDialog.categoryClasses`), whose Set/Clear API key button opens `_ApiKeyDialog` and whose "Synthesizer for navigation" choice is applied on save; plus gestures NVDA+Shift+U (credit usage), NVDA+Shift+V (recheck voices/models) and an unassigned toggle for the navigation synthesizer. It lazily imports `API_BASE` and `checkApiKey` from `synthDrivers.elevenlabs`, calls the driver's `_fallBack` when the key is cleared, `retryAfterFallBack` when one is set, and `useNavigationSynth`/`navigationSynthDescription`, so keep those names stable. The module name is kept so users' remapped gestures still apply.
- `addon/locale/<lang>/LC_MESSAGES/nvda.po`: translations. Strings use `_()` and `pgettext("label", ...)` with `# Translators:` comments; `buildVars.py`'s summary, description and changelog are translatable too (they feed the translated manifests). When adding or changing a translatable string, update every `.po` by hand (check with `msgfmt -o /dev/null <po>`); scons compiles the `.mo` files.

## Settings and the API key

- **Settings file, not NVDA config**: the API key and learned account state live in `elevenlabs_settings.json` in NVDA's config folder, read and written only through `_elevenlabsSettings` (`get`, the `editing()` context manager, `invalidateChecks`). It caches the parsed file, so hand edits made while NVDA runs are overwritten. Writes are atomic (temp file + `os.replace`); an unreadable file is renamed to `.bad`. Top-level keys: `apiKey`, `outputFormat`, `checkVoices` (`false` turns the voice check off), `voiceChecks` (`{model: {fingerprint, unusable}}`), `modelCheck` (`{fingerprint, unusable}`), `refusedFields` (`{model: [field, ...]}`), `navigationSynth` (the synth name speaking outside say all; absent means off), `lastNavigationSynth` (what the toggle switches back to). Removing a key forces it to be worked out again. Old `.txt` settings files are ignored on purpose. User-facing voice settings (rate, stability, model, etc.) are normal NVDA driver settings.
- **API key**: `apiKey` holds the key encrypted with Windows DPAPI (`CryptProtectData`, per Windows user, with add-on-specific entropy), base64 encoded. `getApiKey`/`setApiKey`/`clearApiKey` keep the decrypted key cached in memory; the driver reads it through `_settings.getApiKey()` on every request. A config copied to another user or PC can't decrypt it, so the key must be set again there. The key is only ever sent to `API_BASE` in the `xi-api-key` header; `checkApiKey` validates a new key with `GET /v1/voices` before the dialog saves it. `SynthDriver.check()` returns False without a key, which hides ElevenLabs from NVDA's synthesizer list (NVDA only calls `check()` when building that list, so a saved ElevenLabs synth without a key still reaches `__init__`, which raises and NVDA falls back).

## Driver architecture (elevenlabs.py)

- **Models**: `MODELS` maps model IDs to `ModelInfo` (supported `voice_settings` fields, realtime vs. slow timeouts, max speed, text split sizes, audio tag support). The account's model list decides which are offered (`_offeredModels`); unknown models start out assumed to accept all settings, and refusals (HTTP 400 naming a field) are learned into `_refused`. Only settings the current model takes are shown (`_get_supportedSettings` via `_SETTING_API_NAMES`). `DEFAULT_MODEL` (Flash v2.5) is used for probes and as the fallback when the chosen model refuses.
- **Probing**: at startup, voices and models are probed with tiny requests (`PROBE_TEXT`) on thread pools with deadlines; results are cached against an account fingerprint so they aren't redone every start. `_classifyRefusal` sorts HTTP errors into voice/model/account/transient categories. Bump `VOICE_CHECK_VERSION`/`MODEL_CHECK_VERSION` to invalidate cached results when probe logic changes.
- **Speech pipeline**: `SynthDriver.speak` queues text + index commands to `_SpeechWorker` (one background thread). It splits text into parts (`_splitText`, sentence-aware), starts a `_Download` thread per POST to `/v1/text-to-speech/{voice}/stream`, prefetches the next part while the current one plays, and feeds PCM to an `nvwave.WavePlayer`. Cancellation bumps `generation`; stale jobs/downloads are dropped by checking `_isCurrent(gen)`. Index callbacks and `synthDoneSpeaking` are always fired even on failure, since NVDA's speech queue waits for them.
- **Say all**: NVDA sends the next utterance only after the current one's last index, and say all reads a sentence (2026.3+) or line at a time, so jobs spoken while say all runs (`_Job.sayAll`) are handled differently. `_IndexSchedule` reports indexes as the part they fall in starts playing (`feed(onDone=...)`), and the trailing ones as soon as the last part has downloaded. The worker then fetches the next utterance's first part ahead (`_prefetchNextJob`) and waits `SAY_ALL_IDLE_GRACE` before `player.idle()`, which blocks until playback ends. Index-only utterances in say all wait for the audio before them (`_afterPlayed`), since NVDA's say all ends on one.
- **Audio**: `OUTPUT_FORMATS` is tried from best to worst until the plan accepts one (`_useNextOutputFormat`). Rate maps to API `speed` within `API_SPEED_RANGE`; anything beyond is done locally with sonic. Volume is applied in software.
- **Audio tags** (`[whispers]` etc.): for models with `tags=True`, a tag is carried over to subsequent parts/utterances (`_withTag`), and an NVDA `processText` filter (`_installTagFilter`/`_hideTags`) protects brackets from NVDA's own processing; tags are stripped for models that would read them aloud.
- **Navigation synthesizer**: when `navigationSynth` is set, ElevenLabs stays NVDA's synth but holds a second driver made with `synthDriverHandler.getSynthInstance` (as `setSynth` does, so it reads its own `config.conf` settings; eSpeak if that fails). `speak`/`cancel`/`pause` go to `_speaker()`: ElevenLabs only while a user-started say all runs (`_isUserSayAll`, i.e. `startedFromScript`). NVDA's speech manager drops notifications from any synth but `getSynth()`, so `NavigationSynth` re-notifies its index/done notifications as ElevenLabs'; `_get_supportedCommands` returns the speaking synth's commands; profile switches reload its settings via `config.post_configProfileSwitch`. Brackets hidden by `_hideTags` are put back (`_unhideTags`) before another synth gets text.
- **Fallback**: if ElevenLabs becomes unusable mid-session (offline, out of credits, bad key), `_fallBack` switches to eSpeak on the main thread via `queueHandler` without changing the saved synth. With a navigation synth it instead sets `_fellBack` and everything goes to that synth with no more API calls (`_isGivenUp`); transient failures (`transient=True`) only do so after `MAX_TRANSIENT_FAILURES` in a row, and a say-all utterance that got no audio is spoken by the navigation synth meanwhile (`_handOver`/`_speakInstead`). `retryAfterFallBack` (new key, NVDA+Shift+V) clears it.
- Anything that touches the GUI or switches synth must go through `queueHandler.queueFunction(queueHandler.eventQueue, ...)` / `wx`; worker threads must not call it directly.

## Conventions

Follow NVDA code style: tabs for indentation, camelCase for functions/attributes, `_get_x`/`_set_x` property accessors for driver settings, `log` from `logHandler` with an `ElevenLabs:` prefix. Comments explain *why*, in plain sentences; match that density.
